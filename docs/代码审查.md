## 已知未修（权衡后决定保留）

| 问题 | 说明 |
|---|---|
| 表读写无锁 | `tracker_scan_feed()` 在 NimBLE host 任务写，UI 任务读。最坏情况是读到"半新半旧"的计数（比如共 N 台比分类之和大 1），不会崩溃。加锁会给扫描热路径引入争用，暂不加 |
| `esl_ble_stack_hold()` 已无调用者 | 扫描改到组件内部后，这个占用计数没用了。保留是为了万一以后别的功能要占用协议栈；`esl_ble_release()` 里的判断相当于免费保险 |
| 扫描和价签共用射频 | 物理上只有一个射频，扫 8~12 秒期间价签会等；手动扫描会抢占推图（价签有重试，不丢） |

## 第二轮：网页 ↔ 板子 联调审查（v2.27.1）

### 方法

1. 把网页 `send()` 的命令全列出来，逐个核对固件是否支持
2. 把网页 `renderStatus()` 读的字段全列出来，和板子 `GET` 实际返回的字段做**集合比对**
3. 协议边界实测：值里带 `=`、带空格、中文、超范围、超长
4. 抓帧路径：头格式、长度、校验

### 发现问题

| 级别 | 问题 | 影响 | 修法 |
|---|---|---|---|
| **P1** | `GET` 不返回 `rot`，网页却读 `o.rot` | 屏幕方向下拉框永远显示 0；**一保存就把方向重置成 0°** | `GET` 补 `cJSON_AddNumberToObject(root, "rot", cfg.rot)` |
| **P1** | 我上一版加的「回读校验」从不生效 | `waitAck(8000)` 默认把带 `cfg` 的回复当状态轮询排除 → 每次都 8 秒超时，静默跳过 | 显式传入 `o => !!o.cfg` |
| P2 | 网页抓帧不校验 | 帧被日志插脏时，界面显示错位画面还以为正常 | 解析头部 xor8，逐字节算，不一致自动重抓一次 |
| P2 | `flog` 每 20 秒落盘一次 | 一天 4300+ 次写（含擦页），对闪存寿命不划算 | 改为「攒够 2KB 或满 60 秒」 |

### 核对通过的部分

| 项 | 结果 |
|---|---|
| 网页发出的命令（GET/SET/KEY/VOL/HITO/FLOGC/LOG/LOGF/SHOT/RECONNECT/REBOOT） | 固件全部支持 |
| `SHOT` 头从 `@SHOT 115200` 变成 `@SHOT 115200 <xor8>` | 网页用 `parseInt` 解析长度，**旧格式兼容，不破** |
| 网页读的 41 个字段 | 板子 52 个字段全覆盖，无缺失（已自动比对） |
| `SET` 值带 `=`、空格、中文 | 全部正确保存（`esl_text=a=b c` 原样保留） |
| 超范围/非法值 | `probe_sec=9999`→裁剪；`theme=99`→`err:"theme 范围 0..4"` |
| 日志拉取 | 用 `@LOGEND` 结束标记，20 秒兜底超时，逻辑正确 |
