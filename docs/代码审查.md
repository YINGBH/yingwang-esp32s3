# 代码审查记录

对追踪标签扫描（v2.18 ~ v2.22）这一批代码的审查结论与修复。

## 已修

| 级别 | 问题 | 位置 | 修法 |
|---|---|---|---|
| P0 | 按键任务被阻塞：`on_button` 里直接调 `esl_ble_tracker_scan()`，首次要初始化协议栈（约 15 秒）→ 期间所有按键失效 | `main.c` 扫描页分支 | 新增 `esl_ble_tracker_scan_async()`：立刻置 `busy` 让页面有反馈，实际工作在独立任务里做 |
| P0 | 串口 `SCAN` 同样阻塞命令行十几秒 | `usb_console.c` | 同样改 async |
| P1 | `VivoBook` 被当成 vivo 手机（`strcasestr` 子串匹配） | `tracker_scan.c` `enrich()` | 先判笔记本型号名（VivoBook/ZenBook/IdeaPad/Latitude/Aspire/MateBook/RedmiBook/MagicBook…），命中就不做品牌映射 |
| P2 | 进度到 100% 时 `100%` 三个字符画在 x=200 会顶出右边界 | `main.c` `render_tracker()` | 改 x=188 |
| P2 | 图标"生成了却不生效"：生成脚本写到组件根目录，`main.c` 读 `include/` | `tools/gen_vendor_icons.py` | 输出统一到 `include/`，删掉根目录重复文件 |

## 已知未修（权衡后决定保留）

| 问题 | 说明 |
|---|---|
| 表读写无锁 | `tracker_scan_feed()` 在 NimBLE host 任务写，UI 任务读。最坏情况是读到"半新半旧"的计数（比如共 N 台比分类之和大 1），不会崩溃。加锁会给扫描热路径引入争用，暂不加 |
| `esl_ble_stack_hold()` 已无调用者 | 扫描改到组件内部后，这个占用计数没用了。保留是为了万一以后别的功能要占用协议栈；`esl_ble_release()` 里的判断相当于免费保险 |
| 扫描和价签共用射频 | 物理上只有一个射频，扫 8~12 秒期间价签会等；手动扫描会抢占推图（价签有重试，不丢） |
