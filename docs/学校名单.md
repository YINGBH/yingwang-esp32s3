判断能不能用的关键不是学校名字，而是**校园门户是不是同一套 `*.wlan` 系统**。
下表只列真机验证过的；没列的不代表不能用，先按下面的「怎么加一所新学校」自查。

| 学校 | 运营商 | 门户特征 | 验证码 | 状态 | 验证日期 |
|---|---|---|---|---|---|
| 太原理工大学 | 中国联通 | `*.wlan` 接口、8090 端口、RSA-512、密码双重 base64 | 4 位数字，62×25 | ✅ 真机跑通 | 2026-11-14 |

## 太原理工大学 · 联通校园网

已验证的完整链路（2026-11-14，ESP32-S3 真机）：

| 步骤 | 接口 / 行为 |
|---|---|
| 探测 | `generate_204` 被劫持 → 判定未认证 |
| 建会话 | `index.wlan` 拿回 `wlan_user_ip` / `wlan_ac_ip` / `wlan_user_mac` 等参数 |
| 取码 | `generateVerifyCode.wlan` → `imgVerifyCode.wlan` 拿 PNG（62×25，4 位，字符集 0-8） |
| 识别 | 板载 CNN（本仓库 `model_q.bin`），4 位各自 softmax，任一位置信度 < 0.90 就换一张图 |
| 提交 | `portalLogin.wlan`，密码 RSA-512 PKCS#1 v1.5 加密后**再 base64 两次** |
| 顶号 | 返回「您当前登录的用户已在线」时走 `portalForceLogin.wlan` |
| 收尾 | 跟随 `portalLoginRedirect.wlan`，再探测确认在线 |

要填的参数（三处，都能在网页后台改，不用重新编译）：

| 参数 | 含义 |
|---|---|
| `portal_base` | 门户根地址，形如 `http://<门户IP>:8090` |
| `portal_ac_ip` | AC 地址（登录表单里的 `wlan_ac_ip`） |
| `portal_ssid` | 校园网 SSID，用来判断当前连的是不是校园网 |

> 仓库里这些值一律是占位符（`YOUR_PORTAL_IP` 之类）。**你校的地址请自己填**，
> 不要照抄别人的 IP —— 不同校区、不同运营商的 AC 都可能不一样。

## 怎么加一所新学校

1. **先把参数抓下来**：连上校园网（未认证），双击仓库根目录的 `抓登录.cmd`，或

   ```bash
   python tools/capture_login.py probe
   ```

   它会打印出 `portal_base` / `portal_ac` / `portal_ssid` 三行，直接粘进网页后台或串口。
   细节见 [抓登录.md](抓登录.md)。如果提示"没抓到门户"，大概率是已经认证过或不在校园网里。

2. 看接口路径是不是 `*.wlan`（`probe` 的第 ③ 步会直接告诉你）
   - **是** → 改 `components/portal/`：接口路径、表单字段名、RSA 公钥、判定关键字（4 处左右）
   - **不是** → 这套固件不适用，需要另写协议层；先用 `capture_login.py proxy` 把真登录请求记下来对照
3. 验证码形状不一样（位数 / 字符集 / 尺寸变了）→ 按 [训练指南.md](../训练指南.md) 重训模型
4. 跑通后把一行补到上表：**学校 + 运营商 + 门户特征 + 验证码 + 日期**。
   提 issue / PR 都行。

⚠️ 提交时**不要贴**账号、密码、宽带账号、MAC、内网 IP 这些，只写学校公开信息。

## 说明

- 同一个学校不同校区、不同运营商（联通/移动/电信），门户可能完全不同，要分别验证
- 运营商换了（比如联通换电信）通常意味着门户换了一套，需要重新抓包
- 这张表不构成任何授权或绕过承诺：只是记录「这套协议在哪些门户上验证过」
