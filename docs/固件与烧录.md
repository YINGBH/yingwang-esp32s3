# 固件与烧录

## 先用现成的（最省事）

Release 页挂了一个**整片镜像**，用占位符配置编译的，不含任何真实账号：

```bash
python -m esptool --chip esp32s3 -p COM5 -b 921600 write_flash 0x0 yingwang-v2.15.2-full.bin
```

烧完板子不会立刻联网（WiFi 名还是 `YOUR_WIFI_SSID`），但**网页后台不需要 WiFi**：

1. USB 线插上板子，浏览器打开网页工具（`web/index.html`，或本地 `python` 起个静态服务）
2. 填 WiFi 名/密码、宽带账号/密码、门户地址、AC IP、校园网 SSID
3. 保存 → 板子自动重连、认证

这些值存在 NVS，掉电不丢，以后不用再连电脑。

> 想只更新固件、不动模型和分区表，可以用 Release 里的 `yingwang-v2.15.2.bin`
> 写到 `0x10000`。

## 为什么归档的固件一个都没放

编译时 `main/app_config.h` 的内容会以明文进到镜像里。作者归档的那 20 多个固件
（`yingwang_v1.7.9` ～ `v1.22.1`，外加 `dist/yingwang-v1.14-flash.bin`）**全部含真实的
手机号、宽带密码、家里 WiFi 名、门户 IP、AC IP**，直接发布等于把这些贴到公网。

唯一不含真实凭据的是 `yingwang_oss_1.22.1.bin`（用的 `YOUR_ACCOUNT` 占位符），
但它是 19:24 构建的，早于当天 19:37 / 19:54 两次「换开源字体」的修复，
确认不了里面点阵的字体来源，所以也按保守原则没发布。

Release 里那个整片镜像是**用仓库源码 + `app_config.example.h` 重新编的**，
点阵是 OFL 字体、配置全是占位符，所以能公开。

## 自己编译

```bash
# ESP-IDF v5.5.x（实测 5.5.6，零警告）
idf.py build
```

产物：

| 文件 | 烧录地址 |
|---|---|
| `build/bootloader/bootloader.bin` | `0x0` |
| `build/partition_table/partition-table.bin` | `0x8000` |
| `build/yingwang.bin` | `0x10000` |
| `model_q.bin`（仓库里带的） | `0xC10000` |

```bash
python -m esptool --chip esp32s3 -p COM5 -b 921600 write_flash \
  0x0      build/bootloader/bootloader.bin \
  0x8000   build/partition_table/partition-table.bin \
  0x10000  build/yingwang.bin \
  0xC10000 model_q.bin
```

想合成单个整片镜像：

```bash
python -m esptool --chip esp32s3 merge_bin -o yingwang-full.bin \
  --flash_mode dio --flash_size 16MB --flash_freq 80m \
  0x0 build/bootloader/bootloader.bin \
  0x8000 build/partition_table/partition-table.bin \
  0x10000 build/yingwang.bin \
  0xC10000 model_q.bin
```

## 关于 sdkconfig

仓库同时提交了 `sdkconfig` 和 `sdkconfig.defaults`，两者**内容一致**（defaults 就是 sdkconfig
的完整快照，开着的写 `=y`、关着的写 `=n`）。这样：

- 直接 `idf.py build` 用仓库里的 `sdkconfig`
- 删掉 `sdkconfig`（或全新 clone 后 `idf.py fullclean` + 重新配置）会从 defaults 重建出**完全相同**的配置

> 为什么要显式写 `=n`：NimBLE 的 peripheral / broadcaster 角色、GATT server 这些 Kconfig
> 默认是 `y`，不显式关掉，重建出来的固件会比 Release 里大 46 KB，蓝牙行为也不一样。
> 实测过：删掉 sdkconfig 重建后，`sdkconfig` 与仓库版本 **0 行差异**，`yingwang.bin` 同为
> 1,464,848 字节。

里面已经包含必须项：16MB Flash（对齐 `partitions.csv`）、八线 PSRAM、NimBLE 全套、
FreeRTOS task snapshot（`TASKS` 命令要用 `uxTaskGetSystemState`）。

## 为什么 `model_q.bin` 进仓库

它是验证码模型，不含任何配置，也不随版本变（模型换了才会变），
放在仓库里别人不用自己训练就能先跑起来。见 [训练指南.md](../训练指南.md)。
