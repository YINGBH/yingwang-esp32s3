# 踩坑记录

调试时踩过的坑，每条都写了真实原因。别人照着查能省时间。

## 认证 / 协议

| 现象 | 原因 |
|---|---|
| 验证码一直 `Errorcode: 0001` | ① SSID 被当成小写提交 ② 同名 Cookie 叠加 ③ WiFi 断连导致请求残缺 |
| 密码怎么都对不上 | 门户要的是 RSA-512 PKCS#1 v1.5 + 两层 base64；用裸模幂加密会失败 |
| 能登录但马上掉线 | 门户把会话和客户端 IP 绑了，登录前必须带参数访问一次 `index.wlan` 建立会话 |
| 直接开 `/portalLoginRedirect.wlan` 是 500 | 那页没有登录框，必须走带 `wlanacname` 参数的 `index.wlan?...` |

## 屏幕 / 字体

| 现象 | 原因 |
|---|---|
| 屏幕上汉字显示成方块 | 忘了重新生成字库：`python tools/gen_font.py`（会扫源码里用到的所有汉字） |
| 屏幕满屏噪点 | 三色墨水屏必须整屏发送，只发变化区间会让数据整体错位 |
| 某个字显示成 `?` | 字库里没有这个字：往 `中文补充.txt` 加，或重跑生成脚本 |
| 编译报路径含中文 | 工程路径、用户名路径都必须纯英文，否则 ccache / binutils 报 ANSI 错误 |

## 电子价签

| 现象 | 原因 |
|---|---|
| 墨水屏第一次推要 40 秒 | `BLE_GAP_EVENT_DISC_COMPLETE` 没处理，扫描超时后干等全局超时 |
| 推图日志说成功但屏没变 | 调的是 `esl_ble_prepare()`（只渲染），不是 `esl_ble_push_info()`（真推） |
| 推完和手机抢连接 | 价签同一时间只能被一个主机连，推之前先断开手机 App |

## 两个「看起来像 bug」的假警报（已核实）

| 现象 | 真相 |
|---|---|
| 诊断页 / `LOG` 里看到的都是开机那几行日志，像是"日志不刷新" | **不是 bug**：串口工具打开 COM 口会拉 DTR/RTS 让板子复位（日志里会重新出现 `esp_image` 那几个段）。复位后 3 秒抓屏，环形缓冲里当然只有开机日志。用 `LOGF` 看时间戳就知道是最新的；想避免就关掉工具的自动复位（`--no-reset`） |
| 日志告警 `内存整理(登录后)：空闲 82KB 最大块 34KB —— 低于推送门槛 60KB`，看着像"这次价签没推" | 这条只是 `app_mem_tidy()` 的**警告**，不拦推送。实测同一次开机的 34 秒后「每日刷屏」照样 `ESP_OK`。真正决定推不推的是 12 点那次判断（见下） |

## 已修：推送门槛用错了指标

12 点定时推价签时，原代码是「先按**最大连续块**决定要不要整理内存，再用**总空闲**决定要不要延后」——
碎片多的时候（空闲够、最大块不够）会误判成能推，BLE 一分配就失败。

现在两处都按最大连续块判断：整理后再量一次 `heap_caps_get_largest_free_block()`，
不够就延后 5 分钟（`main.c` 的定时推送分支）。

> ⚠️ 更正：这段分支被 `#if ENABLE_PERIODIC_ESL_PUSH` 包着，而该宏是 **0**（默认关闭），
> 所以它在现成固件里**根本没编进去**。真正在跑的每日推送是「联网 30 秒后刷一次墨水屏」，
> 那条路径原来没有内存检查，已补上：推之前若最大块 < 60KB 先 `app_mem_tidy()`。

## 墨水屏缺字：「毛毛雨」显示成「雨」（v2.1.1 修）

现象：价签上天气写「毛毛雨」，屏上只有「雨」；「中雨」「冻雨」「雷暴冰雹」也一样缺字。

原因：墨水屏用的是独立的点阵字库 `components/esl_ble/esl_font.h`，由
`tools/gen_esl_font.py` 生成。它的字表 = 手写的基础字 + **自动扫描几个源文件**，
而扫描列表里只有 `esl_ble.c` / 日历数据 / `esl_ble.h` —— **没有 `time_weather.c`**，
而「毛毛雨/中雨/冻雨/雷暴冰雹」这些词正好只写在那里面。

修法：把 `components/net_clock/time_weather.c` 加进 `AUTO_SCAN`，重新生成：
汉字 654 → 697，`毛`/`中`/`冰`/`雹`/`冻`/`粒`/`强` 都有了。

验证：重新推信息页后 dump 画布（`ESLIMG`），天气那行三字完整：「毛毛雨」。

> 教训：**画面上出现的任何文字，其来源文件都必须在字库的扫描列表里**。
> 彩屏点阵（`gen_font.py`）扫的是 `main/` + `components/` 全部文件，所以没缺；
> 墨水屏那份当初只扫了三个文件，漏了天气。以后加新的中文文案，改完跑一次
> `python tools/gen_esl_font.py` 就不会再缺。

## 网页上的「录音」面板是假的（v2.0.1 已移除）

现象：网页后台有一块「录音（存在板子 flash 里，掉电不丢）」，点了「刷新列表」报"读取失败"、
点「全部清空」报"清空失败"。

原因：**固件从来没实现过这三个命令**。网页等的是 `RECLIST` / `RECGET` / `RECCLEAR`，
而 `usb_console.c` 里只有 `RECONNECT`（重连 WiFi），未知命令一律回 `@{"ok":false,"err":"unknown"}`。
板端只剩 `audio_rec_start/stop` 这套采集 API 和 `REC_SECONDS` 之类的宏，没有任何地方把 PCM
落到 flash，也没有按键录音/回放。

处理：把这块面板连同 150 行 JS（列表、导出 WAV、清空、接收状态机）一起删掉 ——
界面上不留点了会报错的假功能。以后真要做录音，需要补：录音任务 → storage 分区存储与索引 →
三个命令 → 网页列表/导出。

> 麦克风本身是好的（`audio_level_*` 读数正常），只是"存成语音备忘"这条链路没写完。

## 网页工具 + 固件复查（v1.26.0 / v1.26.1）

这一轮重点看 `web/index.html`（900 多行 JS）和新加的省电逻辑。

### 网页工具

| 问题 | 说明 | 修法 |
|---|---|---|
| **XSS：设备字符串直接进 innerHTML** | 状态卡片是 `innerHTML` 拼的，`SSID` / `IP` 来自板子（也就是来自周围热点）。一个叫 `<img onerror=...>` 的热点就能在这个页面里跑脚本，而**这个页面握着 Web Serial 权限** | 加了 `esc()`，所有设备回来的字符串先转义 |
| **`waitAck` 会被状态回包抢答** | 页面每 3 秒发一次 `GET`，它的回复也是 `@{"ok":true,...}`；`SET` / `BGC` / 抓帧的等待队列是谁先到谁拿走 → 命令没成功也可能显示"已完成" | `waitAck(ms, pred)` 按内容挑应答：带 `cfg`/`version` 的状态回包不算命令应答 |
| **抓帧没有超时** | 板子不回复时 `shotMode` 永远为真：按钮卡在"抓取中…"，而且 GET 轮询被永久停掉，页面像死了一样 | 40 秒超时，恢复按钮并清状态 |
| **自动重连竞态** | 重连时旧 `readLoop` 的 `finally` 会把**新**连接的 `reader`/`writer` 清空、还会再触发一次重连 → 页面反复"连上又断开" | 加连接代次 `connId`，旧回路收尾时直接退出 |
| **日志跨包乱码** | `feedLog` 每个 chunk 新建一个 `TextDecoder`，一个汉字被拆在两个 USB 包里就变 `�` | 解码器挂在 `logMode` 上复用 |

### 固件（新省电逻辑）

| 问题 | 说明 | 修法 |
|---|---|---|
| **低亮度常显的画面是冻住的** | `ui_task` 在 `s_screen_off` 时直接 `continue`，背光虽然亮着，但时钟/运行时长都不再更新 | 新增 `s_aod`：常显模式下继续绘制（1 秒一帧），只有真正全黑才停 |
| **常显时不跑防残影** | 翻转刷新的条件是 `!s_screen_off`，AOD 下永远不触发 | 条件改成 `(!s_screen_off || s_aod)` |

验证：AOD 下抓两帧相隔 3 秒，**1093 个像素不同** → 画面确实在更新（改之前是 0）。

### v1.26.1 又补了两处

| 问题 | 说明 | 修法 |
|---|---|---|
| **截完图把全局日志级别改回 INFO** | `SHOT` 为了不让日志混进二进制流，原来用 `esp_log_level_set("*", ESP_LOG_NONE)` 静音，结束时再设回 `INFO`。这会把别的模块**单独调过的级别**（比如把某个 tag 调成 WARN/DEBUG）一起冲掉 | 改成临时换 `esp_log_set_vprintf` 钩子（`shot_log_sink`），结束后换回原钩子 —— 完全不碰日志级别 |
| **保存配置不检查结果** | 网页「保存配置」一口气发 15 条 `SET`，谁失败都不看：板子回 `unknown_key` / `nvs` 时界面照样显示"已下发" | 改为逐条 `await waitAck(6000)`，失败项汇总进日志并弹窗列出 |

验证：截完图（115,930 字节）之后 8 秒内串口上照常出现新日志（4 行）→ 钩子确实换回来了；
网页重新渲染后状态区正常回填 → JS 无语法错误。

## 屏幕残影（image sticking）——不是固件 bug

现象：屏幕上**一直**留着一层状态页文字的影子，**切页也不消失**，过很久才慢慢淡。

原因：这块 1.54 寸 IPS 面板（ST7789）在长时间显示同一幅高对比画面时，
液晶分子被同一组电压定住，会"记住"这幅画面。状态页恰好是最容易留下残影的组合：
亮黄色标题条 + 纯白大字压在纯黑底上，放几个小时就印上去了。

判断方法：**抓帧（`SHOT`）里是干净的**——帧缓冲没问题、刷屏也没丢带
（日志里 `刷屏 ok=2430 超时=0`）。所以残影只存在于面板玻璃上，不在代码里。

固件能做的两件事（v1.24.1 起）：

| 措施 | 位置 | 说明 |
|---|---|---|
| **熄屏时清屏** | `pm_tick()` | 关背光的同时把整屏刷黑，面板不再被固定画面"烤"着（背光已 0，看不到这一下） |
| **亮屏时定期翻转** | `ui_task()` | 每 30 分钟整屏刷 黑 → 白 → 黑 再重画当前页，把累积电荷冲掉；`ANTI_STICK_MIN` 改 0 可关闭，改小更频繁 |

> 充电时屏幕常亮（`pm_tick` 直接 return），所以"插着电一直显示状态页"是最容易出残影的用法，
> 定期翻转这条在这种情况下尤其有用。

已经印上的残影会随着显示不同画面慢慢退掉；退回不掉的属于面板老化，只能换屏。

## 扫描把加密随机字节当成主机名

**现象**：SCANTOP 里出现 `"name":"n]4g"`、`"SooK"`、`"{/(BO"` 这种名字，而且 5 台设备被标成「电脑」。

**原因**：微软厂商数据（Company `0x0006`）里有 Swift Pair 和加密广播两类。
我一开始的策略是「在这段数据里挑最长的可打印 ASCII 串当名字」，
加密载荷的随机字节自然也能凑出 4-5 个可打印字符，于是全被当成名字，还顺带把类型判成电脑。

**修法**：只在整段广播里找 **`LAPTOP-` / `DESKTOP-` / `PC-` / `WIN-` 前缀**的 ASCII 串；
微软分支只认 Swift Pair 子类型 `0x03`，不再看载荷内容。

**验证**：附近那台 Windows 笔记本（`LAPTOP-2H4DOI4Q`）能被正确识别成「电脑 1」，
其余 6 台照旧归「手机」，垃圾名字消失。

## 查结果时板子总是 0 台

**不是 bug**：ESP32-S3 的 USB 串口一打开就会通过 DTR/RTS 复位板子，
扫描结果存在 RAM 里，复位就没了。所以 `SCAN` 和 `SCANTOP` 必须在**同一个串口会话**里发。

## 墨水屏一直显示「认证中」，认证成功也不变

**现象**：板子明明已认证（网页/串口都显示在线），墨水屏状态栏还是红色的「认证中」，重新推几次也不变。

**原因**：推图时有一段"复用预渲染画面"的优化——

```c
bool fresh = (s_img_built_ms > 0) && (s_img_built_info == s_want_info) &&
             (now2 - s_img_built_ms <= IMG_FRESH_MS);   // 10 分钟
if (!fresh) { draw_info(); }        // 现画
else { /* 直接复用这张图 */ }        // ← 完全不看认证状态
```

离线时推过一次，缓存里就是一张写着「认证中」的图；10 分钟内再推，**直接复用**，
于是认证成功了屏上还是「认证中」。

**修法**：记录缓存画面对应的认证状态 `s_img_authed`；主循环每次在线都会调
`esl_ble_note_authed()`，里面发现「缓存不是已认证」就作废缓存并清 `s_last_img_valid`
（否则 `push_common` 会以"画面没变"为由跳过推送）。

**验证**：`EPDCACHE RESET` 伪造一张未认证缓存 → 等主循环认证 → 日志出现
`认证状态变了：作废缓存画面（下次推送会重画）`，之后再推就会现画「已认证」。

> 注意：**屏上的图不会自己变**。墨水屏只在推送时更新，认证成功后要么等下一次推送，
> 要么手动推一次（价签页长按 BOOT）。
