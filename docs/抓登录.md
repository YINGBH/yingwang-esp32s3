# 抓登录（电脑端脚本）

换一所学校，第一步永远是**把门户参数抓下来**：门户地址、AC 的 IP、校园网 SSID，
以及"这套门户到底是不是 `*.wlan` 那一套"。

`tools/capture_login.py` 就是干这个的，**纯标准库、不用装任何东西**（Python 3.8+）。

```bash
python tools/capture_login.py check     # 现在到底有没有网
python tools/capture_login.py probe     # 探参数（最常用）
python tools/capture_login.py probe --json portal.json
python tools/capture_login.py proxy     # 起代理，记录浏览器真登录的请求
```

Windows 上也可以直接双击仓库根目录的 **`抓登录.cmd`**。

> 提示：`.cmd` 里的用法说明是**英文**的。原因是 cmd 按系统代码页读批处理，
> 而代码页因机器而异，中文 `echo` 很容易变成 `锟斤拷`/`?`；脚本自己的中文输出
> 会**跟随控制台代码页**（`GetConsoleOutputCP()`），936 和 65001 都试过，显示正常。
>
> 另外这个 `.cmd` 会自己找 Python：先用 `python`/`py -3`，找不到再去
> `%LOCALAPPDATA%\Programs\Python\Python3*` 和 `C:\Espressif\tools\idf-python\` 里找，
> 所以**没配 PATH 也能双击跑**。

## 不想装 Python？用免安装 exe

Release 页有一份打包好的 **`capture-login.exe`**（单文件，约 8.8 MB，不用装 Python）：

1. 下载它，和 `抓登录.cmd` **放在同一个目录**（都放桌面也行）
2. 双击 `抓登录.cmd` —— 它会优先用 exe，界面上会显示 `using: capture_login.exe (no Python needed)`
3. 也可以直接双击 exe，或者在命令行里 `capture_login.exe probe`

exe 是 PyInstaller 打的 `--onefile` 包，运行时会把自身解到 `%TEMP%` 再跑：

- 首次启动约 1–2 秒（解包），之后也差不多（每次都要解）
- **`%TEMP%` 必须可写**；如果公司电脑把 TEMP 锁死，会报
  `Could not create temporary directory`，那就用 Python 版
- 个别杀软会把 PyInstaller 的单文件包误报成可疑程序（没签名的通病），
  不放心就用 `python tools/capture_login.py`

## 一、probe：不用代理、不用登录

前提：**电脑连着校园网、还没认证**（如果已经能上网，门户不会拦你，自然抓不到）。

```text
① 探测当前网络有没有被门户拦
  http://connectivitycheck.platform.hicloud.com/generate_204
    -> HTTP 302，跳到 http://10.0.0.1:8090/index.wlan?wlanuserip=...&wlanacip=...&ssid=...
...

② 抓参数
  wlanuserip   = 10.20.30.40
  wlanacip     = 10.0.0.1
  wlanacname   = AC-XXX
  ssid         = 校园网-SSID
  门户地址      = http://10.0.0.1:8090

③ 判断这是不是 *.wlan 那套门户
  http://10.0.0.1:8090/index.wlan                 HTTP 200  存在
  http://10.0.0.1:8090/generateVerifyCode.wlan    HTTP 200  存在
  验证码已存到 capture/captcha.png（735 字节）

④ 结果
  ✅ 看着就是 *.wlan 这套

  串口里这样填：
    SET portal_base=http://10.0.0.1:8090
    SET portal_ac=10.0.0.1
    SET portal_ssid=校园网-SSID
```

拿到这三行，直接粘进串口 / 网页后台（或写进 `main/app_config.h`）就行。

**验证码**会顺手存一张到 `capture/captcha.png`：打开看尺寸和字符集，
和固件自带的 62×25、4 位、`0-8` 对得上就不用重训；对不上就按 [训练指南.md](../训练指南.md) 重训。

### 几个常见结论

| 输出 | 含义 | 下一步 |
|---|---|---|
| 四条探测全 204/200，没抓到门户 | 已经认证过，或不在校园网 | 断开认证/换设备，连校园 WiFi 再跑 |
| 302 跳到门户、`*.wlan` 存在 | 同一套系统 | 填三个参数即可 |
| 302 跳到门户、`*.wlan` 全 404 | 不是同一套门户 | 用下面的 `proxy` 看真请求 |
| 全部连不上 | DNS/网络不通 | 先修网络 |

## 二、proxy：记录浏览器真登录时发的请求

适合"门户长得不一样"的情况：它会把**请求行、表单字段、Set-Cookie、Location** 全记下来，
用来对照着改 `components/portal/`。

```text
代理已启动：127.0.0.1:8888
日志：capture/proxy-20261115-131500.log
接下来：
  1. 浏览器/系统代理设成 127.0.0.1:8888
  2. 随便打开一个 http 网站，等门户跳出来，正常登录一次
  3. 回到窗口看记录（密码字段已经打成 ***）
  4. Ctrl+C 结束
```

记录长这样：

```text
>>> 13:15:42 POST http://10.0.0.1:8090/portalLogin.wlan?1700000000
    Referer: http://10.0.0.1:8090/index.wlan
    Cookie: JSESSIONID=...
    body: loginmode=static&passType=1&wlanAcName=AC-XXX&wlanAcIp=10.0.0.1
          &wlanUserIp=10.20.30.40&ssid=...&userName=138****0000&userPwd=***&verifyCode=8570
    <<< HTTP 200
    Set-Cookie: JSESSIONID=...
```

> 密码、宽带账号都会被打码（只留首位尾位），但**日志里仍然有账号的一部分和 cookie**，
> 别直接贴到 issue 里。

代理只处理**明文 HTTP**（校园门户基本都是 HTTP）。要抓 HTTPS 的门户就得装证书，
那是另一套东西，这个脚本故意不碰。

## 三、拿到参数之后

1. 填进设备：网页后台三项，或串口 `SET portal_base=... / portal_ac=... / portal_ssid=...`
2. 跑一次认证，看串口日志：
   - `验证码被拒` → 验证码识别不对，按训练指南重训
   - `用户名或密码错误` → 看是 RSA/表单字段不一样，用 `proxy` 对照
3. 能稳定上网了 → 把「学校 + 运营商 + 门户特征」补进 [docs/学校名单.md](学校名单.md)

## 四、它能测什么、不能测什么

**能**：门户地址、AC IP、SSID、是不是 `*.wlan`、验证码长什么样、登录表单字段名。

**不能**：RSA 公钥（在页面 JS 里，`proxy` 能看到 JS 响应但解不出来）、
验证码模型的准确率、运营商的认证策略（限速/多设备）。

RSA 公钥在门户的登录页 JS 里，一般是 `modulus`/`exponent` 或一段 Base64。
`proxy` 模式下把登录页 JSON/JS 的响应存下来，搜 `modulus`、`exponent`、`publicKey` 就能找到。
